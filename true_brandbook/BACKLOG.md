## Библиотека ассетов (раздел «Исходники»)

- **Раздел «Библиотека / Ассеты»** в интерфейсе с подразделами: **Продукты** (пиццы-каталожки + позже додстеры/картошка/наггетсы/напитки), **Шрифты** (Rooftop, Noto Sans — превью, они вшиты в рендер), **Ассеты** (логотип, графика, фоны), **Референсы** (эталонные макеты, уже есть), **Прочее**. NB: «исходники» = ассеты для сборки макета, НЕ тяжёлые PSD/AI. Развитие текущего `/admin/materials`. Открытый вопрос: только админ управляет или все видят (склонялись к «админ правит, все смотрят»). Расширить `brand_materials.kind` под категории + тип продукта (пицца/додстер/напиток) через теги или отдельное поле
- **Продуктовый каталог — добор**: догрузить остальные сорта пицц (Chicken Wasabi + классика: Маргарита, Мясная, Четыре сыра, BBQ, Дьябло, Двойная пепперони), затем P2 (додстеры/картофель/наггетсы), P3 (напитки: пепси/кола/кофе/лимонады/милкшейки). Источник — Google Drive («… — App.png» рендеры). Блокер: Drive-коннектор нестабилен, отваливается после нескольких файлов — нужен надёжный реконнект
- **Загрузка своего фото продукта** маркетологом под конкретную генерацию (fallback, когда нужного нет в каталоге)

## UX / Интерфейс

- Офферы с количеством (2=1, комбо, «две пиццы»): решить, как показывать (одна пицца + акцент «2=1», либо N картинок продукта). Сейчас показывается одна — для «2 по цене одной» это несостыковка
- Макет «без продукта» (нет совпадения по каталогу) выходит пустоватым — панель под фото зияет. Докрутить: в этом случае заполнять композицию типографикой/графикой, а не резервировать дыру под фото
- Fun статусы генерации пока идёт ожидание (типа "замешиваем пиксели...")
- Браузерные push-уведомления когда генерация готова (пользователь ушёл со страницы)
- Настройка приватности activity feed (некоторые компании не хотят показывать кто что делает)
- Мобильная оптимизация формы генерации

## Безопасность рендера

- Заменить regex-пре-фильтр `validateHtml()` на настоящий санитайзер (DOMPurify + jsdom, whole-document) перед хранением и повторным рендером HTML
- Chromium в контейнере запускать под non-root пользователем с setuid-sandbox вместо `--no-sandbox`
- Deny egress рендер-процесса к `169.254.169.254` и RFC1918 на сетевом уровне (Railway) — defense-in-depth
- (сделано в прототипе) граница безопасности перенесена в рендер: JS выключен + перехват сети (только `data:`/`about:`) — SSRF/скрипты закрыты независимо от regex
